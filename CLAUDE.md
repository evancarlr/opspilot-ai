# OpsPilot AI — Development Instructions

## Project
OpsPilot is an AI-powered business operations analyst.

Initial domain: customer onboarding at Relay Technologies, OpsPilot's first
fictional customer. Relay sells RelayOS, a cloud warehouse fulfillment
operations platform, to e-commerce retailers and 3PLs.
See docs/relay-business-context.md.

## Data and evaluation
- Analysis inputs: data/synthetic/ (generated by src/opspilot/generate_data.py).
- Evaluation only: data/evaluation/ground_truth.json. Never expose it to the
  analysis agent.
- Keep docs/relay-business-context.md free of the planted problems; it may be
  given to the agent as background.

## Stack
Python 3.12, uv, pandas, NumPy, DuckDB,
Pydantic, pytest.

Future: Anthropic API and Streamlit.

## Development principles
- Keep solutions simple and maintainable.
- Separate analytics from AI reasoning.
- Never fabricate business metrics.
- Write tests for important functionality.
- Use reproducible synthetic data.
- Distinguish correlation from causation.
- Document architectural decisions.

## Claude Code workflow
1. Inspect the existing repository.
2. Propose a concise implementation plan.
3. Implement the requested scope.
4. Run tests and fix errors.
5. Summarize design decisions.
6. Stop at the requested milestone.

## Guardrails
- Do not commit changes automatically.
- Do not install dependencies without approval.
- Do not use real customer or patient data.
- Never expose API keys.

## Current Milestone
Milestone 1 (complete): synthetic Relay onboarding data.
Milestone 2 (complete): deterministic analytics engine in src/opspilot/analytics/
(see docs/analytics.md). It must never read data/evaluation/.
Do not build the LLM agent or frontend until Milestone 3 is requested.
